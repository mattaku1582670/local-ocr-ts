# 後工程課題

正式仕様を黙って変更せず、現在のWBSを止めるほどではない課題を、解決すべき後工程とともに記録する。

| ID | 課題 | 影響 | 対応予定 |
|---|---|---|---|
| DI-001 | GitHub CLIを権限制約によりインストールできず、初回commit/pushを保留している。remoteも未設定。 | リモート履歴とバックアップがまだない。ローカル成果物には影響しない。 | GitHub CLIまたは利用可能な認証手段が整い次第実施し、遅くともWBS 22.16のリリース可否判断前に解消する。 |
| DI-002 | portable OCR自動試験で、モデル初期化が180秒以内に完了しない事象が1回発生した。直後の再試験は104秒で英数字・日本語OCRとも成功し、再現していない。 | 初回展開、Windows Defender、端末負荷による起動・初期化時間のばらつきが利用体験に影響する可能性がある。 | WBS 21.10で単一EXEと展開済みフォルダ版を反復測定し、WBS 22.14の総合E2Eでもcold startを複数回確認する。 |
| DI-003 | 1920×1080 cold runではメモリ余裕が小さく、A4 300dpi相当では最大working set 2,393.57 MiB、最大private memory 4,030.17 MiBとなり1.5GB目標を超過した。warm壁時計中央値31.88秒も20秒目標を超過した。 | A4原寸処理は低メモリPCでメモリ不足やUI不安定化を招く可能性があり、Gate Aの速度・メモリ条件に不適合である。 | Gate A採用条件として、WBS 12.4、12.5、12.8、12.9、22.13でピクセル上限・安全な縮小・座標復元・巨大画像試験を完了する。原画像は変更しない。 |
| DI-004 | WBS 2.18の50画像はユーザー承認済みの合成暫定セットであり、実スクリーンショット・実撮影文書を含まない。 | 合成画像では実利用時の精度を過大評価する可能性があり、最終Gateの精度根拠としては不足する。 | WBS 22.14のOCR精度再評価までに、匿名化・人手確認済みの実画像50件以上へ追加または置換し、同じCERランナーで再評価する。 |
| DI-005 | Python 3.13.13 / PaddlePaddle 3.3.1の既定oneDNN経路でPIR属性変換の未実装例外が発生し、比較PoCでは`enable_mkldnn=false`が必要だった。 | Gate Bを採用した場合にCPU高速化を利用できず、速度・互換性・固定バージョン管理へ影響する。 | Gate Bを再検討する場合はPaddlePaddleの修正版または別の再配布可能なPythonバージョン組合せで回帰試験する。Gate A採用時は比較資料として保持する。 |
| DI-006 | Python比較PoCの未最適化`.venv`は811.15 MiBで、Python runtime・PaddlePaddle・PaddleXのportable同梱は未検証である。 | Gate Bは配布サイズ、起動、ライセンス一覧、脆弱性管理、IPC監視の対象を増やす。 | Gate B採用時のみ、埋め込みruntimeを最小化してportable・日本語/空白パス・offline・ライセンスをWBSへ追加検証する。 |

## DI-001 再開時の確認事項

- 意図しない生成物、モデル、秘密情報がcommit対象に含まれていないことを再確認する。
- `main`へ現状を1つの基準commitとして記録する。
- remote `origin`を`https://github.com/mattaku1582670/local-ocr-ts.git`へ設定する。
- GitHub認証状態を確認してpushする。
- push後のremote branchとcommit SHAを照合する。
