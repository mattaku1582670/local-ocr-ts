# WBS 2.14 日本語パス・空白パス試験

## 結論

単一portable EXEを空白を含むディレクトリと日本語を含むディレクトリへそれぞれコピーし、両方で起動とOCRに成功した。各ケースで英数字と日本語を認識し、ローカルモデル、WASM、Workerが使用され、外部HTTP/HTTPS要求は0件だった。

WBS 2.14の完了条件「起動・OCR成功」を満たす。

## 試験パス

試験ごとにOSの一時ディレクトリ直下へ専用ディレクトリを作成し、次の相対配置を検証した。

| ケース | 配置パス |
|---|---|
| 空白パス | `local-ocr-path-e2e-<random>/path with spaces/Local OCR portable.exe` |
| 日本語パス | `local-ocr-path-e2e-<random>/日本語パス/Local OCR portable.exe` |

ディレクトリ名だけでなくEXE名にも空白を含む。コピー後に元のportable EXEとファイルサイズおよびSHA-256が一致することを確認してから起動した。

## 自動試験

`scripts/test-portable-paths.mjs`を追加し、`npm run test:e2e:portable-paths`で再実行可能にした。

自動試験は次を行う。

1. releaseディレクトリのportable EXEが1件だけであることを確認する。
2. OS temp配下へ識別可能な専用一時ディレクトリを作る。
3. 空白パスへEXEをコピーし、サイズとSHA-256を照合する。
4. EXEを起動し、英数字・日本語OCR、モデル/WASM/Worker、外部通信0件を確認する。
5. 日本語パスでも同じ検証を行う。
6. 成否にかかわらず、検証済みの専用一時ディレクトリだけを再帰削除する。

子テストが停止した場合に備え、各ケースへ210秒の親側ハードタイムアウトを設けた。タイムアウト時に終了するのは、テストが起動したNode子プロセスを起点とするプロセスツリーだけである。

個別再試験用に`--case space`と`--case japanese`も用意した。通常のnpmスクリプトは両ケースを順番に実行する。

## テスト競合の解消

最初の日本語パス試験では、HTML表示後かつrendererのイベント登録前にテストがボタンを操作し、画面がidleのままタイムアウトした。パスや資産読込の失敗ではなく、テストのready判定不足だった。`DOMContentLoaded`に加えて50ms間隔のUI heartbeatが1以上になるまで待つよう修正した。

また、2回目のOCR開始時に前回の`success`を今回の完了と誤認する競合があった。各操作で必ず`working`への遷移を確認してから`success/error`を待つよう修正した。

これらの修正後、空白パスと日本語パスを連続実行する最終試験は114秒で成功した。
