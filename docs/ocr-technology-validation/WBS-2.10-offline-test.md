# WBS 2.10 ネットワーク遮断試験

## 結論

production browser PoCを、外部ホストへ通信できないよう強制したMicrosoft Edge headless上で起動し、ローカルモデル初期化、英数字OCR、日本語OCRが成功した。アプリから外部HTTP/HTTPS要求、通信失敗、ページ例外は発生しなかった。

この結果により、PaddleOCR.js、ONNX Runtime Web、検出・認識モデル、WASM、Workerの実行経路がオンライン資産へ依存しないことをPoCで確認できた。

ただし、Windowsのネットワークアダプター自体は無効化していない。現在の実行権限では`Get-NetAdapter`もアクセス拒否となり、アダプター無効化は管理者権限を要するうえ、開発セッションを切断するシステム変更になる。したがって正式受入基準AT-003の「ネットワークアダプター無効状態」は、portable版完成後のWBS 21.11および22.9で実機QAとして残す。

## 遮断構成

専用の`playwright.offline.config.ts`で通常E2Eとは異なるlocalhostポートを使用し、次の多層構成で外部通信を遮断する。

1. Edgeへ`--disable-background-networking`を渡し、ブラウザ自身のバックグラウンド通信を停止する。
2. `--host-resolver-rules=MAP * ~NOTFOUND, EXCLUDE 127.0.0.1`を渡し、localhost以外のホスト名解決を失敗させる。
3. PlaywrightのBrowserContext routeで、localhost以外のHTTP/HTTPS要求を`internetdisconnected`として通信前に中断する。
4. OCR開始前に専用ページから外部URLへの制御用ナビゲーションを行い、routeが実際に中断したことを確認する。
5. 制御用要求を除き、アプリからの外部要求または中断対象が1件でもあれば試験を失敗させる。

この構成は、外部DNS名だけでなく、アプリが直接外部IPアドレスを指定した場合もBrowserContext routeで遮断する。localhostのproduction previewとローカルOCR資産だけを許可する。

## 試験内容

単一の新規ブラウザセッションで次を実行した。

1. 遮断制御用の外部URLが通信前に中断されることを確認する。
2. production previewのトップページを起動し、初期状態が`idle`であることを確認する。
3. 英数字サンプルOCRを開始する。
4. 検出・認識モデル、ORT WASMがlocalhostから要求されることを確認する。
5. Worker／WASM構成で`LOCAL OCR`と`TEST ABC 123`を認識することを確認する。
6. 同一セッションで日本語サンプルOCRを実行し、`日本語の文字認識`と`東京 2026`を認識することを確認する。
7. アプリの外部HTTP/HTTPS要求、予期しない遮断、失敗要求、ページ例外がすべて0件であることを確認する。

同一セッション内で2回OCRすることで、初回モデル初期化と初期化後の再利用を両方確認する。

## 判定範囲

WBS 2.10の技術検証として、production browser PoCが外部通信を強制遮断された条件で起動・モデル初期化・英数字／日本語OCRを完了することは確認済みとする。

一方、詳細要件定義書8.3に含まれる編集、コピー、TXT/JSON保存はPoCに未実装であり、今回の試験対象外である。正式AT-003はportable版でこれらの導線を実装した後、ネットワークアダプターを実際に無効化して判定する。

## 残存リスク

- production JavaScriptに依存ライブラリ由来の外部URLリテラルが11件残る。
- Electron sandbox、CSP、`file:`またはカスタムプロトコルで同じローカル資産解決が成立するかは未検証である。
- portable版での起動、保存、移動後の資産解決は未検証である。
- OSレベルのネットワークアダプター無効化試験は未実施である。
- ブラウザPoCには編集、コピー、TXT/JSON保存機能がないため、完全なオフライン受入導線は未検証である。

## 完了条件

自動化可能なブラウザPoC範囲の「完全オフライン成功」は達成した。WBS 2.10の実装・技術検証を完了とし、OSアダプター無効化を含む正式AT-003のQA判定は未完了として追跡する。
