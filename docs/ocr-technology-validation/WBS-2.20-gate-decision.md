# WBS 2.20 Gate A/B採用判断

- 決定日: 2026-08-10
- ステータス: 承認済み
- 決定: Gate A（PaddleOCR.js + ONNX Runtime Web / WASM）

## 推奨判断

**Gate A（PaddleOCR.js + ONNX Runtime Web / WASM）を採用する。**

Python版は同一50画像で精度がほぼ同じ、平均処理時間が1.67倍で、oneDNN互換性問題と大きな同梱依存を追加する。Gate Bへ切り替えても現在の主要課題であるA4 300dpiの速度・メモリを改善できる根拠がないため、複雑性と攻撃面を増やす選択は妥当でない。

ただし、A4 300dpi原寸入力の性能不適合は解消済みとはしない。既存WBS 12.4「最大ピクセル数設定」、12.5「安全な縮小処理」、12.8「縮小後座標復元」、12.9「前処理比較試験」、22.13「巨大画像試験」をリリース必須条件として扱う。原画像ファイルは変更せず、OCRへ渡す作業用画像だけを縮小する。

2026-08-10の継続指示を承認として記録し、WBS 2.20を完了とする。

## 採用後の制約

1. `OcrEngine`インターフェースを正式境界とし、UIへPaddleOCR固有処理を書かない。
2. 初期実装は`paddleocr-js`だけを生成し、未使用のPython runtimeを製品へ同梱しない。
3. A4/巨大画像対策をWBS 12.4、12.5、12.8、12.9、22.13で完了するまで、性能要件を達成済みと報告しない。
4. 最終実画像CER、portable offline、cold start、メモリ、ライセンス成果物のいずれかが不合格なら、WBS 22.16でリリースを止める。
5. Gate Bは交換可能な境界として維持するが、必要性が再発するまでPythonサイドカーを実装しない。
