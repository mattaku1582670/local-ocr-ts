# WBS 2.17 20画像連続OCR試験

## 結論

同一Electronセッション、同一OCRエンジン、同一Workerで1920×1080 PNGを20件逐次処理し、20件すべてでOCRに成功した。クラッシュ、要求失敗、renderer例外、外部HTTP/HTTPS要求は発生しなかった。

WBS 2.17の完了条件「クラッシュなし」を満たす。

## 試験条件

- 1920×1080 PNGを20件生成する。
- 各画像には異なる連番とDocument IDを描画し、別ファイル名で投入する。
- 画像には日本語、英数字、記号を含める。
- OCRは逐次実行し、同時実行数を1とする。
- モデルとWorkerは初回初期化後に再利用する。
- 各処理で画像寸法、WASM backend、Worker実行、空でないOCR結果を検証する。
- 100ms間隔でElectron全プロセスのworking setとprivate memoryを測定する。
- 画像およびOCR本文は保存・ログ出力しない。

## 結果

| 指標 | 結果 |
|---|---:|
| 成功 | 20 / 20 |
| クラッシュ | 0 |
| 外部HTTP/HTTPS要求 | 0 |
| 要求失敗 | 0 |
| renderer例外 | 0 |
| Worker生成 | 1 |
| 壁時計中央値 | 5.01秒 |
| 壁時計最大 | 11.08秒（初回モデル初期化を含む） |
| エンジン時間中央値 | 4.86秒 |
| 最大working set | 1,382.61 MiB |
| 最大private memory | 1,473.14 MiB |
| 1件目後から終了安定後のworking set差 | +27.57 MiB |
| 1件目後から終了安定後のprivate memory差 | +33.97 MiB |

初回後のworking setは概ね1,196～1,294 MiBの範囲で上下し、処理件数に応じた単調増加は見られなかった。20件目後に2秒待った安定値はworking set 1,268.96 MiB、private memory 1,320.09 MiBだった。

各OCR中のUI heartbeat増分は86～221で、全20件で進行した。Worker処理中もrendererのイベントループが応答していることを再確認した。

最大private memory 1,473.14 MiBは1.5GiB未満だが余裕が小さい。10進1.5GBとしては超過するため、正式な単位定義と実機条件の追加評価は引き続き必要である。ただし本WBSの主目的である20画像連続処理の安定性は達成した。

機械可読な各runの値は`WBS-2.17-continuous-ocr.json`へ保存した。

## 自動試験

`scripts/test-continuous-ocr.mjs`を追加し、`npm run test:continuous-ocr`で再実行可能にした。

テストは失敗時もElectronを終了し、既存プロセスを対象にせず、自身が起動したアプリだけを閉じる。

## 完了条件

20画像を同一セッションで逐次OCRし、異常終了せず全件成功したため、WBS 2.17を完了と判定する。
